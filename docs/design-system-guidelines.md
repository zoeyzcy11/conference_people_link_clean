# 学术会议知识库 设计系统规范（v1）

## 1. 设计目标
- 信息优先：先让用户快速定位会议，再进入人物和 workshop 细节。
- 结构清晰：以“筛选 -> 沙盘 -> 详情”为主导航路径。
- 可信感：弱装饰，强调数据字段和官方链接。

## 2. 视觉令牌（Design Tokens）
- 主色：`accent #194057`
- 辅色：`accent2 #4c7464`
- 背景：`mist #f6f1e8`
- 卡片：`panel #fffaf3`
- 边线：`line #ded4c4`
- 文本：`ink #162332`

## 3. 字体与排版
- 正文：`Noto Sans SC`
- 展示标题：`Space Grotesk + Noto Sans SC`
- 主标题层级：
  - H1：40-48px（首页主标题）
  - H2：24-30px（模块标题）
  - H3：18-20px（卡片/分区标题）
- 正文字号：14-16px；说明文字：12-13px

## 4. 间距体系
- 基础步进：`4px`
- 常用间距：
  - 组件内边距：`p-4 / p-5 / p-6`
  - 模块间距：`space-y-5 / space-y-6`
  - 卡片圆角：`rounded-2xl / rounded-3xl`

## 5. 组件规范
- FilterDrawer：
  - 桌面端固定侧栏 + sticky
  - 移动端使用 Sheet/Dialog
  - 必须展示“已选条件数量”和“清空筛选”
- DataTable：
  - 桌面端固定列宽，移动端允许横向滚动
  - 日期列使用等宽风格，链接列可直接外跳
  - 行点击进入详情，外链点击不触发行跳转
- Stat Cards：
  - 首页至少包含：总会议数、官方信息完整数、当前命中数

## 6. 信息可视化规范
- 首版图表只做轻量可读：
  - 领域分布条形图
  - 数据质量摘要卡
- 每个图表必须可追溯到字段，不允许虚构指标。
- 色彩只用系统色，不新增随机强调色。

## 7. 数据质量规范
- 会议必须有唯一 `conferenceId`。
- `url` 必须是 `http/https`。
- 日期字段使用 `YYYY-MM-DD`。
- `conferenceStart <= conferenceEnd`。
- 允许缺失，但缺失必须显式标注为“待官网公布/待补充”。

## 8. 开发与发布建议
- 每次数据更新先运行：
  - `npm run validate:data`
  - `npm run build`
- 通过后再发布，避免“页面可打开但数据结构破损”。
